# Prajakta Inamke Portfolio

## Goal

Build a polished, responsive multi-page portfolio that presents Prajakta as an experienced independent web developer and turns professional visitors into project enquiries.

## Pages and navigation

- Create shared sticky navigation, animated mobile menu, footer, and enquiry calls-to-action.
- Build separate routes for Home, About, Services, Portfolio, Experience, and Contact.
- Build reusable dynamic case-study pages at `/portfolio/$slug`, including previous and next project navigation.
- Keep every navigation item and call-to-action connected to a real route or external profile destination.

## Design and content

- Establish a warm off-white, deep-charcoal, restrained accent design system with premium typography, editorial spacing, soft shadows, and minimal rounding.
- Build the homepage around a browser/device project showcase, credibility strip, services, selected work, process, technology groups, working principles, testimonials, and final enquiry call-to-action.
- Create distinct long-form content and layouts for About, Services, Portfolio, Experience, and Contact rather than repeating homepage sections.
- Use clear placeholder labels only where real portraits, project screenshots, testimonials, and profile URLs are not supplied.

## Interactions

- Add working portfolio category filters and route-based case-study navigation.
- Add a client-side validated project enquiry form with service preselection from service-page links and clear success feedback.
- Add restrained reveal, image-hover, navigation, carousel, and button motion with reduced-motion support.

## Reusable structure

- Centralize projects, services, experience, testimonials, and technology content in editable data modules.
- Create shared layout, page-heading, project-card, call-to-action, and section components.
- Use the existing TanStack routing system and existing interface components.

## SEO and accessibility

- Add unique title, description, canonical URL, Open Graph data, Twitter card, and semantic heading hierarchy to every content route.
- Add Person, WebSite, and ProfessionalService structured data where appropriate.
- Ensure keyboard-friendly navigation, visible focus states, labeled controls, useful alternative text, and touch-friendly mobile controls.

## Verification

- Check every route and sample case-study URL in desktop and mobile viewports.
- Verify navigation, mobile menu, filters, service preselection, form validation, testimonial controls, and previous/next project links.
- Confirm there are no dead actions, placeholder template content, route errors, console errors, overflow, or overlapping text.
